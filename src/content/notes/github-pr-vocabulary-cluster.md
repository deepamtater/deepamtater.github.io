45% of GitHub pull requests now share the exact same vocabulary cluster.

A researcher scraped 47,464 pull requests across five million words to see how developers describe their code.

The word "load-bearing" is now 123 times more frequent than it was two years ago. Other top words include "quietly," "survived," "latent," "seam," and "genuine."

Engineers stopped writing PR descriptions. When Cursor or Claude Code finishes a task, developers copy the conversational summary and paste it straight into GitHub.

A five-line utility fix gets described as protecting a load-bearing seam across the codebase. It sounds polite and thorough, but it is pure noise.

When every pull request uses the same ten agent adjectives, reviewers stop reading the text and look only at the diff.

If a developer cannot explain their change in two plain sentences, the agent understood the patch better than they did.
